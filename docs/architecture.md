# Architecture

SafeScreen Edge is a web app that runs its whole analysis pipeline on the device. It is built to run in a normal browser today and inside a Windows host (WebView2) on Snapdragon X Series PCs, where the model stages move to the NPU.

## Layout

```
src/
  inference/        AI engine (no React)
    preprocess.ts   frame scaling, dark-theme inversion
    ocr.ts          Tesseract worker, returns text + line boxes
    context.ts      URLs, sensitive-value detection and masking, UI hints
    structure.ts    navigation / actions / issues, region labeling
    agents/         error, risk, UI and general agents
    analyze.ts      runs agents, picks the most specific result, masks secrets
    assistant.ts    local question answering over an analysis
    providers.ts    local, scenario (demo), native host, cloud fallback
  runtime/          hardware integration layer
    probe.ts        device capability probe (arch, WASM SIMD, WebGPU, WebNN, host)
    nativeBridge.ts WebView2 bridge to the SafeScreen Windows host
    plan.ts         stage-by-stage execution plan (today vs Snapdragon target)
  store/store.ts    settings, local history, activity log, measured runs
  app/              application shell, session (capture + analysis), palette, presentation
  pages/            marketing pages and pages/app/* product pages
  components/       design system components
```

## Pipeline

```
capture -> preprocess -> OCR (+ line boxes) -> UI detection -> context
        -> agents -> evidence -> response + regions -> optional local history
```

Every provider implements one interface:

```ts
interface InferenceProvider {
  id: 'local' | 'scenario' | 'native' | 'cloud-demo';
  availability(): { ok: boolean; reason?: string };
  analyze(input, onStage, { signal, exclude }): Promise<AnalysisReport>;
}
```

`onStage` events drive the pipeline UI. Each stage is timed with `performance.now()` and tagged with the backend it ran on. The report also counts resource requests made during the run, so the UI can show whether anything left the page.

Provider order at runtime: native host if connected, otherwise local browser OCR. Cloud fallback is never automatic; it is offered after a local failure only if the user allowed it, local-only mode is off, and an endpoint is configured.

## Agents

Agents are deterministic rules over recognized text, so results are explainable and repeatable:

- **Error agent**: Python, Node, .NET, Java and shell errors, long logs (key lines and likely location).
- **Risk agent**: sign-in pages vs. domain, elevation prompts, payment pressure, paste-this-command instructions. Wording is "potentially suspicious", never "malicious".
- **UI agent**: application screens (navigation, primary action, messages that need attention).
- **General agent**: fallback with what was read.

Each result separates observations (with their source), interpretation, actions, evidence lines and a confidence level with its reason. Confidence is a rule-based level, not a probability.

## Regions

`labelRegions` turns positioned text lines and the analysis into labeled boxes (ERROR MESSAGE, PASSWORD FIELD, PRIMARY BUTTON...). The same code runs on live OCR line boxes and on the prepared text layout of demo scenarios. Each region records where its position came from.

## Demo mode

Demo scenarios (`src/demo`) are SVG screens generated by `scripts/make-demo-images.py` with a matching transcript, text layout and simulated vision annotations. They run through the same agents and region labeling, and are labeled "Demo Simulation" everywhere. Any demo image can also be analyzed with real OCR from the Live Analysis page.

## Checks

- `npm run check:agents` prints agent output for every scenario and edge case.
- `npm run build && npm run test:e2e` runs the browser suite against the production build, including real OCR under the production Content Security Policy.
